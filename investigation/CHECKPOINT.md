# phase05-001 — manual GitHub token verification and storage

Adds a collapsed Account settings section and the standard themed token top sheet: masked input, hidden permission help, horizontal divider, equal-width Create token/Save token actions, keyboard-safe layout and vertical opening/closing animation. A successful fixed-endpoint GitHub account lookup saves the token and public login/avatar profile; the token is supplied at runtime to the previously tested repository delivery layer. Fields and error messages do not expose credentials.

Uses Android Keystore AES/GCM with private preferences. This differs from the original DataStore preference representation and is an explicit comparison variable if later v2/original behavior diverges. No new dependency or manifest permission is introduced. Stored credentials are excluded from project data. Restarts can read saved credentials; automatic account revalidation, OAuth/device flow, logout, required sign-in gating, avatar popup and expanded token instructions remain separate checkpoints.

Verification: release lint and 46 JVM tests including account identity parsing, status/redirect rejection, bounded responses, invalid header input and sanitized transport errors. Separate same-signature instrumentation receives an ephemeral encrypted runtime credential, enters it through an in-process accessibility action, presses the actual Save token button, verifies encrypted persistence/restart reading and rejects tampered ciphertext. No plaintext token is passed in shell arguments, UI dumps, screenshots or logs. Visual/keyboard/help/cancel checks and manual scans follow OnePlus then Poco.

API reference: [GitHub authenticated-user endpoint](https://docs.github.com/en/rest/users/users#get-the-authenticated-user). Key storage reference: [Android Keystore](https://developer.android.com/privacy-and-security/keystore). No device pass is claimed before observation.
